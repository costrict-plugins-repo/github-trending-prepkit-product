# Interview Type Selection

Choose the lightest interview type that answers the blocked decision.

| Decision Gap | Interview Type | Use When | Avoid When |
|---|---|---|---|
| "Is this problem real and costly?" | Problem interview | Evidence is thin, problem still needs proof | Team already agrees the problem is real |
| "Why do users switch or stay?" | Switching interview | Comparing current alternative vs. change | You only need quick concept reaction |
| "Does this concept address the job?" | Concept reaction interview | Problem is real, concept is still rough | You already have a prototype to test behavior |
| "What happened after trying the workaround?" | Follow-up retrospective | Learning from recent user behavior | The event is old enough that recall is weak |

Rules:
- Prefer problem interviews when the route is still `research` vs. `PRD`
- Prefer concept reaction only after the underlying problem is evidenced
- If the gap is better answered by an experiment, recommend `experiment` to facilitation instead of forcing interviews
