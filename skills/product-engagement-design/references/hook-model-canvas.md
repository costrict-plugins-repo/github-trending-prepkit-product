# Hook Model Canvas

Nir Eyal's four-phase engagement loop. Use it to design for repeated value, not empty repeat usage.

## Phase Map

| Phase | Core Question | Design Elements | Worked Example |
|---|---|---|---|
| Trigger | What brings the user back? | External: notification, email, badge. Internal: emotion, need, or context cue | Slack unread badge |
| Action | What is the simplest behavior? | Lower friction until Motivation x Ability clears activation threshold | Scroll, reply, save, resume |
| Variable Reward | What is the payoff? | Tribe, Hunt, or Self rewards | Social validation, discovery, mastery |
| Investment | What does the user contribute? | Data, content, skill, reputation, preferences | Playlist, profile, history |

## Trigger Progression

External triggers should gradually reinforce internal triggers. If the product only works when you send notifications, the loop is weak.

## Variable Reward Types

| Type | Mechanism | Product Examples | Over-use Risk |
|---|---|---|---|
| Tribe | Belonging, status, recognition | likes, comments, rankings | anxiety, social comparison |
| Hunt | Search for information or novelty | feed refresh, discovery | compulsive checking |
| Self | Mastery, completion, progress | levels, streaks, personal bests | perfectionism, hollow progress |

## Investment Quality Checklist

- [ ] Does the investment improve the next loop?
- [ ] Is the accumulated value visible to the user?
- [ ] Does it create real value retention instead of artificial lock-in?
- [ ] Is the effort proportional to the payoff?

## Loop Health Check

| Symptom | Likely Broken Phase | Fix |
|---|---|---|
| One-time use only | Trigger or reward weak | clarify return reason, strengthen payoff |
| Good D1, poor D7 retention | Investment missing | add profile, preferences, saved state, or skill carryover |
| Opens with no depth | Action too hard | reduce steps between trigger and value |
| Users say it gets boring | Reward too predictable | add freshness or meaningful progression |
