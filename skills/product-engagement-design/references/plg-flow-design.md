# PLG Flow Design

## PLG Funnel Architecture

The PLG funnel inverts the traditional sales-first model: let the product sell itself.

**Core flow:**
1. **Free access** — user enters the product with zero friction and zero cost. No credit card, no trial countdown timer on first visit.
2. **Activation event** — user completes the single action that demonstrates the product works (e.g., completes a practice session, gets a score, sees feedback).
3. **Wow moment** — user experiences undeniable value they cannot get elsewhere. This is not a feature tour — it is the product delivering on its promise.
4. **In-context upsell** — at the moment of peak engagement, present the upgrade path as a natural extension of what the user is already doing.

**Key principle**: every step must deliver value. If any step is a gate rather than a value moment, users leak.

## Show Don't Tell

Design the user path so value is **experienced** before it is **pitched**.

Rules:
- Never describe a feature's benefit in marketing copy if you can let the user experience it directly
- The free experience must be genuinely valuable, not a crippled version of the paid product
- Social proof emerges from usage, not testimonials — "you practiced 12 hours this month" is more compelling than "10,000 users trust us"
- The paywall should feel like a natural progression, not a barrier

Anti-pattern: "Sign up to see your results" — this gates value behind a wall. Instead: show results immediately, then offer deeper analysis as an upgrade.

## Earned-Reward Nudge Pattern

Connect upgrade prompts to **demonstrated user effort**, not calendar time or feature limits.

**Pattern:**
- Track meaningful user actions (practice time, sessions completed, content consumed)
- At effort milestones, acknowledge the effort AND present a reward
- The reward should be a taste of the premium experience, not a discount

**Examples:**
- "You've practiced 8 hours this month. Prep rewards you with 2 expert Writing reviews — keep going!"
- "You completed 20 Listening & Reading sets. Unlock your personalized study plan to see what to focus on next."
- "Your score improved 15 points. Get detailed score analysis to find your remaining weak spots."

**Why this works:** the user has already demonstrated commitment. The upgrade is positioned as a reward for effort, not a sales pitch. The user feels earned access, not marketed-to.

**vs. cold marketing messages:**
- Cold: "Upgrade to Premium for advanced features!" — no context, no timing
- Earned: "You studied 3 hours today — that's dedication. Here's a free deep-dive on your weakest Speaking topic." — contextual, effort-aware, value-first

## Wow Moment Design

The wow moment is the fastest path from signup to the single action that produces **undeniable value**.

**Design process:**
1. Identify the core value proposition in one sentence
2. Find the minimum user action that demonstrates that value
3. Remove every step between signup and that action
4. Measure: what percentage of signups reach the wow moment? That is your activation rate.

**Characteristics of a strong wow moment:**
- User-generated, not system-demonstrated (the user does something, not watches something)
- Produces a tangible artifact (a score, a piece of feedback, a completed exercise)
- Cannot be easily replicated by competitors or free alternatives
- Happens in the first session, not after days of usage

**Example for test prep:** User completes one practice section → gets immediate AI-powered feedback with specific improvement suggestions → realizes this feedback is better than self-study. That is the wow moment.

## In-Context Upsell

Upgrade prompts must be:
- **Contextual** — appear when the user is actively engaged in a related task
- **Non-interruptive** — never block the current flow; appear alongside or after completion
- **Goal-aligned** — the upgrade helps the user achieve what they're already trying to do
- **Specific** — name the exact benefit, not "unlock premium"

**Placement rules:**
- After completing a free activity, not during it
- When the user hits a natural boundary (finished all free content in a category)
- When usage data suggests the user would benefit from a specific premium feature
- Never as a modal popup that blocks the current task

**Format:** brief, specific, tied to current context. Example: "You just finished all free Speaking topics. Unlock 40 more topics with expert-reviewed model answers."

## Anti-patterns

| Anti-pattern | Why it fails | Better approach |
|---|---|---|
| Paywalling before value delivery | User has no evidence the product works | Let them experience the core value loop once for free |
| Modal popup upsells during active tasks | Interrupts flow, creates resentment | Post-completion contextual suggestion |
| Generic "Upgrade Now" CTAs | No specificity, no timing, no context | Name the exact feature and tie to current activity |
| Trial countdown timers as primary pressure | Creates anxiety, not desire | Earned rewards create desire; time pressure creates churn |
| Crippled free experience | User concludes the product is bad | Free experience must be genuinely good; premium is more, not un-crippled |
| Feature comparison tables as primary conversion tool | Rational comparison, not emotional conviction | Let the user experience the feature gap naturally |
