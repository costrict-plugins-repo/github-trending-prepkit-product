# Working Backwards PR/FAQ Template

Amazon's Working Backwards method — write the press release before writing code.

## Press Release Structure (1 page max)

| Section | What to Write | Test |
|---|---|---|
| Headline | Customer benefit, not feature name | Would a non-technical customer understand it? |
| Subheading | Who benefits + what changes for them | Is the audience specific? |
| Problem paragraph | What is painful today, in customer language | Would a real user nod reading this? |
| Solution paragraph | How the product resolves the pain | No jargon, no implementation details |
| Company quote | Why this matters to the company's mission | Does it link to strategy? |
| How it works | 3-4 bullet points, customer's perspective | No engineering terminology |
| Customer quote | What changed for them after using it | Is this believable from a real user? |
| Call to action | What to do next | Is it one clear action? |

## FAQ Structure (2-5 pages)

**Customer FAQs** (answer what users will actually ask):
- How does it work step by step?
- How much does it cost / how does pricing work?
- How do I migrate from what I use today?
- What happens if something goes wrong?
- How is this different from [competitor]?

**Internal FAQs** (answer honestly — this is a thinking tool, not marketing):
- Is this technically feasible in the proposed timeline?
- What does it cost to build and operate?
- What are the top 3 risks and how do we mitigate them?
- What dependencies does this have on other teams?
- What's our plan if this doesn't get traction in 90 days?

## Review Checklist

- [ ] Headline is about customer benefit, not technology
- [ ] Problem paragraph uses language from real user interviews
- [ ] A real user would recognize the pain described
- [ ] Internal FAQs are honest about risks and unknowns
- [ ] Document has gone through at least 3 revision cycles
- [ ] No solution details appear in the problem paragraph
- [ ] Customer quote sounds like a real person, not marketing copy

## Common Mistakes

| Mistake | Symptom | Fix |
|---|---|---|
| PR written about technology | Headline mentions the feature name | Rewrite from customer outcome |
| Internal FAQs skipped | Only 1-page press release exists | Add honest internal risks before review |
| Treated as marketing copy | No hard questions answered | Add devil's advocate FAQ section |
| First draft accepted | Only one version exists | Mandate 3 iterations minimum |
| Written in committee | Document sounds neutral and vague | Assign single author, others comment |
