# Build Trap Assessment

Melissa Perri's Build Trap diagnostic — are you measuring output or outcome?

## Diagnostic Signals

| Signal | Severity | Action |
|---|---|---|
| Team measures features shipped, not behavior changed | Critical | Redefine success metrics as user behavior change |
| Roadmap is a stakeholder feature list | Critical | Switch to outcome-based roadmap |
| "We need to build X" stated without "because users need Y" | Critical | Require problem statement before any spec |
| No one can articulate the product strategy | High | Run strategy alignment exercise before next sprint |
| Discovery happens only at project kick-off | High | Adopt continuous discovery cadence |
| Fewer than 2 of last 5 shipped features moved a key metric | Critical | Stop shipping; start validating |
| PM spends >50% of time writing specs | Medium | Rebalance toward discovery activities |
| Quarterly OKRs are all output-based | High | Rewrite as outcome targets |

## Product Kata (Perri's continuous improvement loop)

1. **Understand direction** — what is the product strategy and current metrics?
2. **Analyze current state** — where are we vs. where we need to be? (gap)
3. **Set next goal** — what outcome do we need next? (behavior change, not feature)
4. **Experiment** — what is the smallest test to move toward that outcome?

Repeat every 1-2 weeks. The answer to step 4 is never "ship the full feature."

## Three Pillars Validation

| Pillar | Question | If No: |
|---|---|---|
| Desirability | Do users actually want this? | Run problem interviews before any design |
| Viability | Should we build this for our business? | Model the economics before committing |
| Feasibility | Can we build this at acceptable cost? | Run a technical spike before planning |

All three must be "yes" before entering a build phase.

## Output vs. Outcome Reframe

| Output (build trap) | Outcome (correct) |
|---|---|
| Ship new onboarding flow | Increase D7 activation rate from 32% to 45% |
| Add search feature | Reduce time-to-first-value from 8 min to 3 min |
| Redesign dashboard | Increase weekly active use of core feature by 20% |
| Build integrations | Reduce churn from "missing integration" by 15% |

## Common Mistakes

| Mistake | Fix |
|---|---|
| Treating assessment as a one-time exercise | Run every quarter; build trap re-emerges under growth pressure |
| Blaming team members instead of the process | Focus diagnosis on system incentives, not individuals |
| Fixing symptoms (add more discovery) without root cause (incentives reward output) | Change how PMs are evaluated, not just what they do |
