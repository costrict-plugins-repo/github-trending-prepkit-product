# Outcome-Driven Innovation (ODI)

Tony Ulwick's ODI — operationalizes JTBD into measurable, prioritizable outcomes.

## Desired Outcome Statement Format

"[Direction] + [measure of performance] + [object of control] + [contextual clarifier]"

| Component | Example |
|---|---|
| Direction | "Minimize the time it takes to..." |
| Measure | "...find relevant results..." |
| Object of control | "...when researching a new topic" |
| Contextual clarifier | "...on a mobile device" |

Full example: "Minimize the time it takes to find relevant search results when researching a new topic on a mobile device."

Rule: never embed a solution in an outcome statement. "Minimize time" is valid. "Use autocomplete to minimize time" is not.

## Job Map (8 Universal Steps)

Every functional job maps to these steps. Find friction at each step to find opportunity.

| Step | Question | Discovery Probe |
|---|---|---|
| 1. Define | What needs to get done? | "What are you trying to accomplish?" |
| 2. Locate | Find inputs needed | "What do you need before you can start?" |
| 3. Prepare | Set up for execution | "What setup or configuration is required?" |
| 4. Confirm | Verify readiness | "How do you know you're ready to proceed?" |
| 5. Execute | Perform the core task | "Walk me through doing the actual task." |
| 6. Monitor | Track progress | "How do you know it's going well?" |
| 7. Modify | Adjust as needed | "What do you change mid-task?" |
| 8. Conclude | Finish and clean up | "How do you wrap up and move on?" |

Interview technique: map every user quote to a job step. Unmet outcomes cluster at specific steps.

## Opportunity Prioritization Matrix

| Importance (1-10) | Satisfaction (1-10) | Opportunity Score | Decision |
|---|---|---|---|
| 8-10 | 1-4 | High (underserved) | Build here |
| 8-10 | 7-10 | Low (table stakes) | Maintain, don't over-invest |
| 1-4 | Any | Negligible | Simplify or remove |
| 5-7 | 1-4 | Medium (monitor) | Watch; validate with more research |

Opportunity Score formula (Ulwick): Importance + max(Importance - Satisfaction, 0)

## JTBD to ODI Bridge

| Method | Tells You | How They Work Together |
|---|---|---|
| JTBD | WHAT job the user is trying to get done | Discover the job through interviews |
| Job Map | WHERE in the job friction occurs | Map all 8 steps; note complaints per step |
| ODI | HOW to measure success at each step | Write outcome statements for each friction point |
| Opportunity Matrix | WHICH outcomes are most underserved | Score importance vs. satisfaction; prioritize gaps |

## Common Mistakes

| Mistake | Fix |
|---|---|
| Outcome statements embed solutions | Rewrite: direction + metric + object only, no technology |
| Job Map skipped — jumping to outcomes | Complete all 8 steps before writing outcome statements |
| Prioritizing without importance + satisfaction scores | Collect both dimensions from same survey sample |
| Confusing ODI outcomes with feature requests | Feature requests describe solutions; outcomes describe unmeasured progress |
| Single user's job map treated as universal | Validate job map across 8-12 users minimum before using for prioritization |
